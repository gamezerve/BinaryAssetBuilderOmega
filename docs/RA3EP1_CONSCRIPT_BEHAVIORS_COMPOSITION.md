## Production ownership and coordinate handling

`Ep1BehaviorMetadataTokenizer.TokenizeContainer` takes only the already compiled
native Chunk and schemas. It accepts bounded, nonempty, canonical native lists
of at most 64 reviewed behavior leaves with distinct nonzero IDs. This bound
does not imply every optional variant of every family is qualified. Empty lists
are explicitly not admitted by this new API.

The native count/header and pointer-array slots must be exact. Ordered module
extents own all remaining native storage. Every relocation/import is bounded;
parent pointer sources are complete; native module pointers cannot cross leaf
owners. Unknown classes, duplicate identities, overlapping/order-invalid leaves,
unowned suffixes and malformed auxiliary arrays fail closed.

Each native owner is locally rebased only for the existing schema/native leaf
tokenizer. Only its **generated metadata** is joined into the parent metadata
prefix. Separately compiled native payloads are never appended: the original
common native buffer is copied once. Metadata-only addresses move to their
new table owner; native metadata targets point to the final common native tail.
Every original native pointer and auxiliary source slot shifts exactly once.
Strong references retain their actual common Core occurrence indices.

The producer receives no stock bytes, offsets, per-asset templates or captured
dependency indices. Existing leaf signature constants and qualification limits
are documented in [the preceding metadata gate](RA3EP1_CONSCRIPT_ALL_BEHAVIORS_TOKENS.md).

## Independent verification and controls

`BehaviorContainerStockProof` reads the stock Behaviors count/marker rows and the
next original root container boundary independently. It requires an exact full
metadata extent, original ordered wrappers and no unowned metadata suffix.
The entire native tail and exact RELO/IMP arrays are independently reconstructed
from the shared input before any detached leaf checks.

Each metadata/native owner is then detached for the existing independent
field-context stock oracle. Every native field and semantic dependency identity
is walked against stock with the **common** Core reference table. The field-path
map distinguishes logical fields that share stock storage. Cross-sibling metadata
table/native targets fail rather than being repaired by a global address map.

The original shared native input remains unchanged and generated outputs repeat
deterministically. **166 shared metadata/input refusals** cover:

- parent count/name/type/marker/target and native-tail corruption;
- every original leaf marker, concrete wrapper/type/table target and native ID;
- missing output RELO/IMP;
- empty/oversized counts, incorrect parent framing, duplicate item pointers/IDs,
  unknown class/zero ID, cross-owner native pointers, orphan storage and missing
  input auxiliary arrays.

Three authored source/Core/Tracker scenarios use the same production container
writer: all 36 in reverse order, all 36 with a newly named helper ID, and eight
mixed original leaves (Squish/CreateObjectDie/death weapon/WeaponSet/SlowDeath/
toggle/StatusBits/HitReaction). The source-selected count, order and identities,
all output native bytes, metadata owner bounds and exact occurrence consumption
are checked. Every unchanged full native leaf is independently compared to stock,
so reference-index reorder cannot substitute a different semantic target. The
renamed helper is explicitly checked as its complete reference-free eight-byte
graph. These are offline source/serialization controls, not gameplay evidence
for arbitrary behavior order or for a complete newly named GameObject.

The earlier **250 leaf metadata/input refusals**, **142 native refusals**,
fourteen authored/refusal controls, one populated two-upgrade-list control and
nine shared native/reference controls remain active. Original source files stay
read-only and hash-bracketed. Source preparation/inheritance limitations are
unchanged; no general source closure is newly claimed.
