## References and native evidence

Linked EP1 static/global catalogs are independently validated. Plain audio names
are resolved uniquely to an actual AudioEvent or Multisound identity, then an
explicit concrete prefix is supplied to Core's reviewed derived-reference path.
This preparation is bounded test-side integration, **not a production-wide plain
audio-reference policy**. Missing or ambiguous names fail rather than selecting
the first match. Other strong fields pass their normal schema-annotated Core path.

Conscript, Ore Collector and Terror Drone normalize to respectively **4, 3 and 5**
strong dependency occurrences. Each target must exist exactly once in the combined
catalog. Every selected stock/Core native reference word is compared by actual
type/instance identity, not dependency-array index; repeated occurrences retain
their own slots. Full selected base/root/state/AI/weapon bytes match after only
proved pointer/reference rebasing. Relocation/import slots and sentinels are checked.
Native dimensions remain those recorded in the direct-module checkpoint.

The test uses the same literal stock-derived source fixtures but **never reads
stock dependency indices to prepare source**. Only the independent comparison
side consults them. Repeats are deterministic. The original captured-index
regression remains unchanged in purpose and continues to run separately.

generic-event text, the EP1 SPECIALABILITY_ACTIVE locomotor and inserted Module
defaults. ModuleId/AIUpdateModuleId and optional listener/invisibility IDs are
checked against an explicit local-ID context before Core normalization. This

Core dependency are also refused; identity comparison cannot merely clear them. Schema
validation now catches an invalid legacy Module trigger instead of relying on its
permissive raw native parser. This does not globally change that legacy parser.
