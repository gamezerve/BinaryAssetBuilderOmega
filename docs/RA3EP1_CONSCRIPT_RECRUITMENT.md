## How the new identity becomes recruitable

The builder emits **two** assets in one linked stream:

1. New tokenized `GameObject:RebornConscriptTrial`, compiled from the selected
   complete XML and independently qualified against the original full graph.
2. Native `LogicCommand:Command_ConstructSovietAntiInfantryInfantry`, recompiled
   from a strict UNIT_BUILD source whose Object reference selects the new local
   GameObject. It overrides the existing stock construction command identity.

The stock Soviet Barracks CommandSet already references this command. It is
not rebuilt/replaced. The same Conscript slot/icon now requests the new object;
all other Barracks choices stay untouched. This is **not an additional menu
entry**, an arbitrary CommandSet editor, or unrestricted custom-ID support.
The original `SovietAntiInfantryInfantry` GameObject is not in this mod stream
and remains stock. Direct original-ID script/map spawns are therefore distinct
from producing the new unit via the redirected construction command. Other
consumers of that same stock command are redirected too.

The command XML is deliberately generated by the bounded compiler profile; no
editable CommandData.xml/inheritance/include frontend is claimed at this stage.
Model, textures, weapon, armor, sounds, command set and other dependencies reuse
stock assets. This is a source-compiled clone, not a wholly original model/unit.

## EP1 command reverse-engineering result

The stock command is in **static.manifest**, not global.manifest:

- TypeId `0x7D464170`; TypeHash `0x751AB28F`; **non-tokenized**.
- BIN/RELO/IMP lengths **32/8/8**.
- Root: 28 bytes, Object pointer at +20 selects +28; +24 is the inactive
  AISpecialPowerInfo pointer. Object import is at +28, one-based selector 1.
- EP1 LogicCommandType omits KW's SELL ordinal and includes COLLECT. All 17
  named enum entries are checked against official EP1 XSD. Only UNIT_BUILD is
  admitted by the new marshaler; optional/options payloads still refuse.

Legacy KW LogicCommand/model/dispatch are unchanged. No stock native payload
is copied as compiler output: newly allocated bytes and auxiliary buffers are
compared against one bounded stock slice as the independent ABI oracle.

## Implementation / validation

- `SageBinaryData/Ep1LogicCommand.cs`: separate EP1 enum and native structure.
- `Marshaler.Ep1LogicCommand.cs`: explicit bounded native allocation route;
  no silent KW fallback or global plugin registration.
- `ConscriptRecruitmentSmokeTest.cs`: official schema/Core reference
  normalization, deterministic actual Tracker compilation, bounded stock
  BIN/RELO/IMP/header/fingerprint comparison, unsupported-source controls.
  The runtime consumer chain is independently checked: the actual Barracks
  token/native CommandSet word is a **weak ID** selecting SovietBarracksCommandSet;
  that set's eight strong command references retain the Conscript command in
  slot two. Weak IDs are not incorrectly required as manifest imports.
- `BoundedDiagnosticBuild.SerializeConscriptRecruitment`: a separate explicit
  two-asset gate; generic tokenized GameObject serialization stays refused.
  Both fingerprints, native bytes/auxiliary tables, fixed identities, six
  scalars and the unique local GameObject import are checked.
- `GameObjectConscriptTrialSmokeTest`: existing complete 49-module/six-owner/
  geometry/126-field/88,824-byte metadata checks remain. The original-ID route
  still reproduces its previous golden BIG. New-ID packages add the checked
  command and read back both assets with ManifestReader and Utility.Manifest.
- Core computes the mixed checksum; repeated serialization must match. Missing
  object, reversed entries, truncated command and wrong import index controls
  must fail before publication. Native/tokenized flags are per entry, not
  guessed from the GameObject.
- Package receipts record AssetCount=2, NewIdentity=true,
  RecruitableNewIdentity=true (offline construction wiring), CommandOverride,
  actual scalar values and GameExecuted=false. This is not gameplay proof.

Internal fast command gate: `conscript-recruitment-command-self-test` with the
static manifest. Users still only use Studio.

## Gameplay check (not automatically launched)

Select the current RebornTest SKUDef in the Uprising launcher and start a **new
Soviet skirmish**, not a saved game. Build Conscript via the normal Barracks slot:

1. Cost should be **15**, production about **2 seconds**.
2. It should retain the stock model/weapons and move faster (Speed=100).
3. Other Barracks choices should remain present and work normally.

The first two values distinguish this new-ID candidate from both stock
(100 / 4 seconds) and the previous original-ID scalar test (25 / 1 second).
Menu load or BIG creation alone is not proof of recruitment. No game process or
installation files are modified by these build/regression checks.
