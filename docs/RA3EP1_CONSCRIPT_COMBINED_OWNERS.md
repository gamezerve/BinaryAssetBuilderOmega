## Source, allocation and production composition

`GameObjectRootOwnersSmokeTest.cs` starts with the existing 49-module source,
then retains the six actual direct children from the captured BaseObject ->
BaseInfantry -> SovietAntiInfantryInfantry chain. The single captured
`ACCOUNT_ORE=0` definition is substituted for BuildCost. Only direct root children
are stably ordered by the admitted compiled official root particle; nested
source ordering is preserved. The enclosing test still brackets all four source
captures with hashes. This explicit preparation does not establish a general
include/inheritance/expression engine or full original root attribute closure.

The complete source is schema-validated and module identities checked before
actual Core normalization. Every named strong dependency must resolve to one
concrete stock catalog target. All 271 occurrence indices are consumed exactly
once by the complete native graph.

`GameObjectBodyProjectionSmokeTest.Compile(..., remainingRoots: true)` detaches
these six source children from incompatible KW dispatch. The new production
`Marshaler.MarshalEp1RootOwners` allocates each reviewed native record after the
existing geometry tail, on the **same Tracker**. No independently compiled native
chunk is appended, and no second reference table is used.

`Ep1GameObjectRootOwnersProjection.Compose` is a separate explicit production
entry point. It validates six distinct ordered tail owners, exact pointer
relocations, auxiliary framing and disjoint ownership. A bounded base view
retains existing selected-root validation with the six pointer slots absent.
Each new owner is independently tokenized by the previously qualified record
writer. The composer joins **metadata only**: six new root rows, existing
metadata and the 2,412 new owner metadata bytes. All native bytes are copied
once from the caller's graph; every native pointer and auxiliary source shifts
once to the final native origin. Common Core occurrence values do not change.

The existing `Ep1GameObjectDestructionProjection.Compose` APIs and narrow/default
profiles stay unchanged. `Ep1GameObjectStringTokens` itself was not broadened:
the separate composer presents its existing validator with a bounded compatible
base view, rather than relaxing its unknown-root ownership check.

## Independent checks on actual composed output

The combined gate verifies the entire transformed native tail and exact RELO/IMP
order against the original shared native graph. Each six-owner native graph is
independently compared with stock, including semantic reference identities and
field-context coordinates. The **actual metadata emitted into the combined
output** is detached, rebased and compared against original stock tables; root
wire tags must match stock too. Reusing the production writer to manufacture
expected metadata would not establish this proof and is not done here.

The existing root/module metadata is separately detached from the actual output,
with only the six inserted root rows and new owner tables removed. All 49 full
module graphs then pass the existing independent stock/native/metadata oracle
with their common 271-entry reference context. Its old exact occurrence-count
check is bypassed **only for this detached subset**; the enclosing combined
oracle checks complete 1..271 consumption once before detachment.

Repeated source builds and composition must be byte-identical, and the producer
must leave its input unchanged. **46 refusal controls** cover old-profile
rejection, six absent/aliased/interior owner pointers, corrupt emitted root
tags/targets/owner tables/native root slots, missing auxiliary streams and
trailing orphan storage. Earlier standalone source-edit/ABI controls and all
49-module source/ownership controls still run separately.
