# Selected GameObject root + complete Conscript Draws

## Outcome and exact boundary

The complete four-module Conscript Draws container now joins the selected
root/armor/movement/Body/three-behavior/common-AI/geometry/vision graph through
**one actual Core normalization pass and one Tracker**. Each combined case has
one occurrence table, not separately normalized component assets.

The largest selected combination reaches **102 partial root fields and 189
strong import occurrences**. All four Draws retain their complete **10 model
states and 84 animation states**. The previously independent **58,608-byte stock
Draws metadata oracle** still matches after root composition; all Draw native
bytes also match the stock-proven standalone graph after pointer/semantic import
coordinate normalization. The authored-edit case preserves the same metadata
topology and checks its new values separately.

This is a selected combined prototype, **not the complete original Conscript**.
Its three supported behaviors/common AI do not replace the original remaining
module families. No complete GameObject stream, mod package, general alpha
admission, recursive source closure or new gameplay is claimed.

## Ownership and writer integration

`Ep1GameObjectDrawRoot.Inspect` identifies the native Draws owner before the
selected behavior tail. Its end is the next independently admitted root owner,
not a guessed fixed size: root strings, armor/movement arrays, pointed root
records/text and inline AI storage remain excluded. Overlap, malformed auxiliary
slots and cross-owner pointers fail before fragment composition. The existing
`Ep1DrawsTokenizer` is reused without a stock template or new reference table.

`Ep1GameObjectDestructionProjection.Compose` appends Draws metadata after the
selected root's other metadata fragments. The root's independently stock-checked
`DrawModules` tag **EFBBA791** points to list metadata, not native pointer slot
472. The entire original native buffer is still copied/rebased once. Absent
Draws emits no additional row or fragment, preserving existing no-Draws layouts;
allocated-empty Draws remains a distinct count-zero list.

The module-local ID scope now covers selected **Body, Behaviors, common AI and
scripted/tracer Draws**. Source and native checks reject collisions across those
classes, including case-folded source IDs. A destruction AssociatedModule link
can resolve to a Draw module within that same object. This is not a general
Poid resolver or gameplay proof of a particular destruction effect.

## Source and verification seam

The combined source uses the unchanged reviewed official `GameObject` type,
not a newly copied focused root schema. The SDK declares that element locally
inside AssetDeclaration, so the test exposes its same type as a standalone
in-memory global element for actual Core normalization. This conditional alias
is diagnostic only; no synced or official XSD is edited.

The prior selected root-source adapter supplies official child order; both full
scripted leaves retain the previously documented particle-order/render-name
preparation. Both official tracers and the separately captured parachute leaf
are kept. The known parachute Script CRLF/LF comparison boundary is unchanged;
the compiler does not rewrite script content or execute LUA.

The explicit EP1 Body/behavior allocator now sets only the reviewed scripted/
tracer class identities before the actual Draw dispatcher runs on the same root
Tracker. No compiled Draw buffer is appended after allocation.
