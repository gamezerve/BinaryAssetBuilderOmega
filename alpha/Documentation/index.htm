Uprising Mod SDK Alpha — live repository workspace

Already-supported value edits now use a shared contract on fixed, variable-module and mixed-asset GameObject builds. BuildCost Amount, MaxHealth, VisionRange, ShroudClearingRange and Locomotor Speed can change together with variable Behaviors, root text and local support assets. Optional UnitTypeIcon/UnitIntro presence is source-driven on these routes too. The compiler still verifies actual serialized values and reference identities; genuinely unimplemented layouts remain errors.

The same build preflight now reports MISSINGSTRING warnings when an XML localization key exists in neither the selected original game CSF nor your Misc/Data/mod.str. Warnings include the owner, field, source file, line and column; they do not stop the build. DisplayName, descriptions and recognized key-shaped string fields are checked. Supported source inheritance/definitions are expanded before lookup. Empty optional values, asset IDs, paths and script bodies are not treated as missing strings. StockStrings in the local SDK configuration selects a language BIG or CSF; only the active data/gamestrings.csf is used, never gamestrings_temp.csf. Missing/broken catalogs generate an incomplete-check warning rather than false missing-key claims. No translations are rewritten.

LogicCommandSet mods may now build without any GameObject. New IDs, stock overrides, source-sized Cmd lists and normal includes/inheritance are supported. Missing Cmd targets are errors. Missing SelectPortrait, ButtonImage (including transformed variants) and CommandSet weak asset names generate MISSINGASSET warnings with the source file, line, column and owner. Lookup checks both emitted mod assets and configured stock manifests; existing image lookup does not require compiling a new image. These weak warnings do not stop the build by themselves.

One complete supported GameObject can now compile alongside multiple ArmorTemplate, WeaponTemplate, LogicCommand and LogicCommandSet declarations in the same mod. Local IDs resolve before stock assets; dependency order is computed from the actual references. DATA includes, definitions and same-type inheritance compose with this route. Declare your UNIT_BUILD command and Barracks command-set override explicitly: no hidden command is generated. Weapon support currently covers the implemented single-DamageNugget layout, not arbitrary nugget structures. The combined new-ID graph is offline-qualified; its gameplay behavior still needs an in-game test.

ArmorSet lists and WeaponSetUpdate hardpoint/Weapon lists support source-sized counts, omission, optional DamageFX/Template/Upgrade imports and nested fields/defaults. The old 32/8/16 trial quotas are removed. Weapons follow official Ordering sorting. Turret/contained weapon slots still need their EP1 processor implementation.

DisplayName and DisplayNameTransformed support changed ASCII text, addition, omission and explicit empty values, together with root descriptions and variable Behaviors. Localization-table entries are separate resources; the compiler does not invent translated text for a new key.

Covered upgrade Behaviors support zero or more TriggeredBy/ConflictsWith entries and optional CustomAnimAndDuration with editable AnimState/Frames/Trigger, including omitted/default attributes. The former 4096-entry tokenizer quota is replaced by actual allocation bounds; other nested layouts still need implementation.

Variable Behaviors now composes with compatible weapon/strong-reference targets and typed upgrade triggers. The former 64-behavior quota is removed; real buffer/depth/ownership checks remain. Missing UpgradeTemplate names are reported with source coordinates. New native layouts and resource processors still need implementation.

This limited candidate uses EA's existing Mod BuildStudio interface. Local user tests confirm sample build success, warning/error display, malformed-XML failure and this documentation pane. This is not full original-SDK feature parity.

A rejected build reports Error: ALPHA100 and Critical: ALPHA101, followed by an alpha build failed message. Successful builds report package paths and Build Completed. Inspect the final receipt; old packages from earlier builds are not new output.

Closing during a build

If this Studio still owns an active build, closing asks whether to cancel it. Yes stops its worker processes and releases the SDK lock before closing. No leaves Studio and the build running. Idle/completed builds do not prompt. Other sessions/processes are untouched. Last-good output is preserved; cancellation cannot interrupt final publication halfway through. The .sdk.lock file may remain normally after its operating-system lock is released. Restart an already-open Studio once to enable this update; earlier uncontained builds are not adopted.

GameObject: schema/native root capabilities

Select RebornTest and click Build Mod. Its data/mod.xml is an EA AssetDeclaration including Conscript.xml (derived unit) and CommandData.xml (explicit command). ConscriptBase.xml is its source-only instance base; DATA:Defines.xml supplies REBORN_CONSCRIPT_BUILD_TIME (currently 2). The selected XML is compiled through Core, native ownership, metadata and reference/stream checks before a fresh BIG is published. This is not a cached BIG export.

Root edits now follow the official schema intersected with reviewed processor ABI registries: 63 primitives plus 15 fixed enum/KindOf/weak-ID attributes, not a six-field gameplay whitelist. Existing nonempty root strong references may also retarget different stock assets one-for-one without changing import count or order. This includes Scale, ThreatLevel, BountyValue, root booleans, Time/Angle/duration fields, both KindOf masks and the EP1 root enums. Existing nested Amount, MaxHealth, VisionRange, ShroudClearingRange and Speed remain editable. No former practical alpha caps apply; values must satisfy the schema and concrete native type, and real values must be finite. Existing root ASCII strings may change content at the exact same byte length. String allocation presence/size, import presence/count and module topology remain unchanged. RebornTest: time=2, cost=15, health=750, vision=400, shroud=700, speed=100, Scale=1.2, ThreatLevel=15.

Custom ASCII IDs are accepted on this same Conscript shape; stock object collisions are refused except the explicit Conscript override. Other edits, arbitrary GameObjects and mixed arbitrary assets are not enabled. ALPHA005 reports this limitation. UprisingXmlRoot in uprising-alpha.paths must point to matching official Uprising XML. The earlier original-ID grouped scalar profile has qualitative user gameplay confirmation, not independent numeric measurements.

EA source syntax and current limits

XML declarations, EA namespace, xsi/xi declarations, comments, empty Tags and local XML Include type=all are supported. Attribute order is flexible. Children must still satisfy the official XSD sequence/list rules. Optional/default omissions work only when they retain the currently admitted unit semantics/native graph.

Attribute-only derived Conscript inheritance, instance Includes, bounded imported Defines/=$NAME expressions and mod-root DATA: XML work. Untouched official Conscript source is not yet directly buildable: general derived child merges, reference Includes, W3X/audio processing and xi:include execution are not connected to this GameObject frontend. Those produce explicit errors, not hidden stock substitutions. Root text keys (including optional display-name children) can resize or change presence. Unsupported module structures and variable-graph strong-import presence changes remain separate capabilities.

DATA/ART/AUDIO search the selected mod before the SDK stock library. DATA defaults to adjacent SageXML; this local SDK contains the original Uprising source copy there, without an external SdkDataRoot override. Short ART names search direct mod Art, mod two-character fanout, then SDK Art fanout. AUDIO searches mod Audio then SDK Audio. Build logs and receipts show the selected physical paths.

Other supported input profiles

The original Reborn sample uses Allied GUN=5000. Archived ArmorCannon uses CANNON=5000 and GUN=100. The archived CombinedArmor fixture contains Allied GUN=250 and Soviet GUN=5000 together. CombinedArmorStrong contains Allied and Soviet GUN=5000 together. Edit mods/<name>/data/mod.xml. One AlliedConYardArmor or SovietConYardArmor, or one of each together, is accepted per build. All thirteen Percent values and five optional root scalars (Default, DamageScalar, SideDamageScalar, RearDamageScalar, FlankedPenalty) accept canonical integers from 0 to 10000; omitted scalars default to 100. Keep the identity and thirteen ordered armor entries. Unsupported input fails; it is not silently skipped. Allied GUN 5000/CANNON 5000 and Soviet GUN 5000 have user-observed gameplay evidence. CombinedArmor has positive Soviet evidence; CombinedArmorStrong has positive Allied evidence. Allied GUN=250 is inconclusive. Soviet was not re-tested in that stronger revision; other edits remain experimental.

The single alpha build step validates XML, compiles through Core and creates a BIG/SKUDef package. Read build.json for the final receipt. Embedded backend paths describe removed intermediates, not live output locations.

The archived ConscriptAK47 fixture describes one complete SovietAntiInfantryInfantryAK47 weapon. Only Damage may change (integer 0..10000, optional .0); all other fields stay as supplied. The sample uses Damage=50. An earlier diagnostic package has user-observed increased damage; new builds remain experimental. Armor and weapon assets cannot share a build in this alpha.

Experimental armor source build

The archived ArmorSource fixture is a three-file Includes/Defines/inheritFrom example producing AlliedConYardArmor and RebornNewArmor; imported bases are not emitted. ALPHA004 warns that this package has no gameplay proof and new IDs need consuming GameObjects.

Armor-only source declarations accept 1..32 owner IDs, 0..64 unique non-ALL damage entries each, and unsigned finite percentages 0..10000 with optional decimals/%. Exact =$NAME fields, reviewed definition forms, local/imported inheritance, directly visible instance bases and Include-free definition-only all leaves are supported. The graph is confined to the mod data root (32 sources, 64 edges, 64 KiB/file, one MiB total). Child replacement by Damage, same-ID source shadowing, definition overrides, arbitrary expressions/all Includes, reference Includes and nonempty Tags are rejected. Read README.md for supported source forms. Old sample routes remain unchanged.

Not supported by this alpha

General GameObject topology/reference/module/string changes beyond current capabilities, other asset types, mixed armor/weapon streams, models, textures, music, maps, LOD selection, STR processing, automatic installation and game launch are not build-enabled here.

Configuration and prerequisites

uprising-alpha.paths contains literal absolute paths: PowerShell7, Driver, StaticManifest, GlobalManifest, CompilerDirectory and UprisingXmlRoot. GlobalManifest is required for weapons/Conscript; UprisingXmlRoot is required for Conscript. Legacy armor configurations remain accepted. Update Driver and CompilerDirectory after relocation. PowerShell 7, x86 .NET 8, compatible .NET Framework 4 and unpacked Uprising stock streams are required. This is a repository-linked development SDK, not a standalone portable distribution.

No stock archive is replaced. The SKU is a mod fragment, not a replacement game SKU. Duplicate identities or unsupported input fail the whole build. New builds are not automatically gameplay-verified.

Local use only: EA components come from your own SDK. Public redistribution review is incomplete.
